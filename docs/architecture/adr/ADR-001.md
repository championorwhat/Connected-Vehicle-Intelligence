# ADR-001: Apache Kafka (KRaft) as the telemetry backbone

**Status:** Accepted (M1), validated with measurements in M3/M4.

## Context
100K vehicles at ~1 event/s, 3× bursts, no data loss, several independent consumers
(normalizer now; ClickHouse sink, detector and batch later), and the ability to replay history
after a bug fix.

## Options considered
| Option | For | Against |
|---|---|---|
| **Kafka (KRaft)** | Durable partitioned log, replay, consumer groups, idempotent producer, ecosystem (ClickHouse Kafka engine) | Heaviest broker footprint (JVM) |
| RabbitMQ | Simple routing, low latency | No cheap replay/log semantics; per-message acks limit throughput |
| Redis Streams | Already in the stack | Memory-bound retention; weaker durability story |
| Pulsar | Tiered storage, multi-tenancy | More moving parts (brokers + BookKeeper) |

## Decision
Kafka 4.1 in KRaft mode. Topics are keyed by vehicle (VIN on raw, vehicle_id on canonical), so
each vehicle's events stay ordered within one partition. The producer uses `acks=all`,
idempotence and lz4. Topics are declared in `kafka/topics/topics.conf`, with auto-creation
disabled.

## Consequences
- Measured: 6.06 M messages produced live at 100K ev/s with 0 delivery failures, and every
  message reconciled (`evidence/benchmarks/m3-simulator-kafka-live-100k.json`).
- One broker locally (8 GB laptop). The 3-broker overlay (RF=3, min ISR 2) survived a broker kill
  with 1,000 of 1,000 `acks=all` writes (`evidence/chaos/m1-kafka-ha-smoke.md`).
- CAP: with `acks=all` + min ISR 2, Kafka chooses consistency over availability for writes
  when replicas are lost (CP within the ISR). See ADR-004.
