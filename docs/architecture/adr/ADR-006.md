# ADR-006: Rules-calibrated planner before ML; money only from sourced costs

**Status:** Accepted (M7).

## Context
M7 turns alerts into decisions: which vehicle to repair first, where and when. The ML model
is scheduled for M8. Repair and downtime costs in the seed are placeholders (zero, with
source `PLACEHOLDER`), and no sourced figures exist yet.

## Decisions
1. **Probability source.** Use calibrated rule probabilities from the back-test now. The
   M8 model replaces them only if it beats them on held-out data. The planner reads a
   versioned calibration file and records `model_version` on every work order, so the two
   can be compared later from outcomes.
2. **No fabricated money.** Rank by `p × (unplanned − planned + downtime × days)` only for
   tenants whose costs are sourced. Otherwise rank by `p × severity`, and leave
   `expected_cost_avoided` NULL. Money in the UI and API is shown only when it is real.
3. **Scheduling.** Greedy by value with the nearest free workshop-day before the deadline
   (algorithms.md A9), not an ILP solver. It is explainable, deterministic, takes
   milliseconds and needs no extra dependency.
4. **Proposals only.** The planner writes `proposed` work orders. A person, or the M9 API,
   confirms them. Every proposal is written to the append-only audit log.
5. **Radar is aggregate-only and single-consumer.** `fleet.signals` carries no vehicle or
   tenant identifiers, because cohorts span tenants and the signals go to OEM-level users.
   One consumer sees the whole fleet: the hot path is under 1 µs per event.

## Options considered
| Option | For | Against |
|---|---|---|
| Plan from raw severity only | Simplest | No deadline, no comparable risk across rules |
| **Calibrated rules + greedy (chosen)** | Measured, explainable, fast | Greedy is not optimal (optimality not measured) |
| Min-cost-flow / ILP (OR-Tools) | Optimal assignment | Heavy dependency; hard to explain; unnecessary at this backlog size |
| Wait for the ML model | Potentially better risk | Blocks the product flow on M8 |

## Consequences
- In the simulator almost every detected fault ends in failure. The per-rule probabilities
  do not beat a base-rate forecast on held-out data (Brier 0.0226 vs 0.0187). Their value
  is the per-rule deadline. This is stated wherever the numbers appear.
- Once real costs are supplied (with a source), ranking switches to money automatically,
  tenant by tenant. No code change is needed.
